# 提示词：eval_single（从文档片段自动生成单轮评测用例）
#
# 占位符用 $name（string.Template 语法），不是 {name}；
# 正文里的 JSON 花括号照常写单括号即可，不用双写转义。
# 加载：app.core.prompts.render("eval_single", title=..., chunk=..., instruction=...)
#
# $instruction 由接口传入：管理员自定义要求，或默认的 FACTUAL_INSTRUCTION
# （见 app/eval/generate.py）。改这里只影响出题问法，不影响逐句原文校验。
#
# ★ few-shot 是决定性的：不给例子时模型爱改写（首轮实测 50 段里只通过 19），
#   给了例子之后通过率大幅上升 —— 这类「照抄」任务上，一个例子顶十条规则。

下面是《$title》里的一段材料：

"""
$chunk
"""

$instruction

严格要求：
1. `ground_truth` 由 1~3 个原文分句组成；多个分句直接用“；”或“。”按原文拼接，
   不要改写、不要概括、不要添加原文没有的连接词。
2. 每个实质分句（≥8 字、含数字或含英文词）都必须是上面材料里的逐字原文，
   不要求连续；所有数字都必须出现在材料里。
3. **问句里不许出现代词**（这个 / 那个 / 该 / 其 / 上述 …）——
   这是**单轮**提问，没有上文，代词会让问题指代不明。
   请用学生自己的处境或要办的事把问题问清楚（如「转专业需要满足什么条件？」）。
   **不要点名文件**：不说出文件名称（如「××管理规定里」），
   也不出现「这份文件」「本办法」「本规定」「该细则」、
   《》书名号或桂电××号之类的文号 —— 真实学生提问很少这样说，
   而且等于把答案所在的文件直接告诉了检索。
4. 只输出 JSON：{"question": "...", "ground_truth": "..."}

示例（假设材料里写着「学生应当在考试前向所在学院提出申请。经批准后方可缓考。」）：
{"question": "缓考要提前跟谁说、什么时候说？", "ground_truth": "学生应当在考试前向所在学院提出申请。经批准后方可缓考。"}
注意答案由两句原文组成，每一句都能在材料里逐字找到。
反面示例（**不要**这样问）：「《本科生管理规定》里的缓考手续要怎么走？」—— 点名了文件。改成：「缓考手续要怎么走？」
