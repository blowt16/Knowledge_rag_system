## 2. A. 空白申请表排除

### 2.1 它是什么

doc 11 第 8 页的表格是**申请表模板**，不是政策条款：

```
学号 |   |   |   | 专业 |   |   |         ← 表单字段行
姓名 |   |   |   | 课号 |   |   |
序号 | 类别 | | 认定内容 | | 成绩 | | 审核人签字   ← 真正的表头
例1 | 科研成果 | | 第二作者，发表论文"XXX"-知网收录 | | 25 | |
例2 | 科研成果 | | 授权实用新型专利-排名第3 | | 10 | |
…（例3–例6）
（4 行全空）
合计 | | | | | 77 | |
```

### 2.2 现状有多坏

现在入库后产出这样的文本：

```
【表头】学号｜｜｜专业｜｜
学号：姓名｜专业：课号
学号：序号｜：类别｜：认定内容｜专业：课号｜：成绩｜：审核人签字
学号：例1｜：科研成果｜：第二作者，发表论文"XXX"-知网收录｜专业：课号｜：25｜：审核人签字
…
学号：例6｜：创业实践｜：参加XX 短期培训并获得结业证书｜专业：课号｜：2｜：审核人签字
学号：例6｜：…（同一行重复 3 次）
学号：合计｜：创业实践｜：…｜：77｜：审核人签字
```

**四个缺陷叠加**：

| 缺陷 | 说明 |
|---|---|
| 表头名是表单字段 | `学号`/`专业` 不是列义，却成了列名 |
| 空列名 | 产出 `：值`（标签是空的） |
| 重复行 | 同一行重复 3 次 |
| 示例行/合计行被当数据 | `例N`、`合计` 是模板占位，不是规则 |

### 2.3 判据（已实测，零误伤）

**表级判据：**

```python
FORM_WORDS = ("审核人签字", "学号", "姓名", "合计", "专业", "课号")

def is_application_form(rows) -> bool:
    flat = [normalize(c) for r in rows for c in r]
    hits = {w for w in FORM_WORDS if any(w in x for x in flat if x)}
    return len(hits) >= 2
```

**实测结果（两份文档共 13 张表）：**

| 文档 | 表 | 判定 | 依据 |
|---|---|---|---|
| doc 11 | p3表1 / p3表2 / p4表1 / p4表2 / p5表1 / p6表1 / p6表2 | **正常** | 命中表单词 0–1 个 |
| doc 11 | **p8表1** | **★表单** | 命中 6 个；空表头 6 个；样例行 6 个 |
| doc 12 | 全部 5 张表 | **正常** | 命中表单词 0–1 个 |

**零误伤。** 注意 doc 12 的 p12 表有空表头 2 个——**低于任何合理阈值**，且不命中表单词 ≥2，所以安全。

### 2.4 落点

在 `load_pdf` 的本地路径里，`extract_page_tables()` 之后、`inherit_headers()` 之前：
把判定为表单的 `RawTable` **从列表中剔除**（不参与序列化、不参与表头继承）。

**被剔除的表格不产生任何 chunk**，其位置也不留占位。

### 2.5 边界

| 情形 | 行为 |
|---|---|
| 命中表单词 ≥2 | **剔除整表** |
| 命中 0–1 个 | 保留（正常表） |
| 表单页上还有**非表格正文** | **保留正文** —— 只剔除表格对象，不动 page text 的其他部分 |
| 表单表同时被判定为「续页」 | 不参与继承链（已被剔除），后续表的 `prev` 自然断开 |

### 2.6 影响

- doc 11 的 chunk 数 **23 → 21**（移除 2 个）
- 索引字数减少 **635 字（约 11%）**
- **doc 12 不受影响**（chunk 数不变）

## 3. B. 裸数字补单位

### 3.1 它是什么

doc 11 的表格里，分值是**光秃秃的整数**：

```
【表头】文章等级｜第1 作者或通信作者｜第2 作者｜第3 作者
文章等级：SCI｜第1 作者或通信作者：100｜第2 作者：80｜第3 作者：60
```

`100` 是 100 分，但字面上没有「分」。读者/模型不知道单位。

### 3.2 实测安全性（关键）

**在 doc 11 非表单的 7 张表里，所有纯整数格的取值范围与分布：**

| 表 | 纯整数格数 | 取值范围 |
|---|---|---|
| p3表1 | 15 | 20–100 |
| p3表2 | 17 | 10–100 |
| p4表1 | 5 | 5–50 |
| p4表2 | 9 | 20–100 |
| p5表1 | 108 | 12–100 |
| p6表1 | 9 | 20–60 |
| p6表2 | 0 | —（值已带单位或含括号说明） |
| **合计** | **163** | **5–100** |

**并且：没有任何一列的表头含「序号」「编号」** —— 即不存在「整数但不是分值」的列。

（唯一含序号的是 doc 11 p8 的申请表单，而它已在 A 里被整表剔除。）

**结论：在非表单表里，给纯整数格补「分」是安全的。**

### 3.3 规则

```python
PURE_INT = re.compile(r"^\d+$")

# 仅对「非表单表格」的**数据行**（不含表头行）生效：
if PURE_INT.match(cell.strip()):
    cell = cell.strip() + "分"
```

**不处理的：**

| 情形 | 行为 |
|---|---|
| 已是 `5 分` / `5分` | 不再追加（幂等） |
| `100（团队其他成员50，入驻场地提…）` | **不追加** —— 不是纯整数 |
| `第1 名` 这类表头 | 不追加（只处理数据行） |
| 空单元格 | 不处理 |
| **申请表单** | 整表已剔除，不涉及 |

### 3.4 效果示例

```
补前：文章等级：SCI｜第1 作者或通信作者：100｜第2 作者：80｜第3 作者：60
补后：文章等级：SCI｜第1 作者或通信作者：100分｜第2 作者：80分｜第3 作者：60分

补前：竞赛类别：A 类竞赛｜获奖等级：一等奖｜第1 名：100｜第2 名：90｜…
补后：竞赛类别：A 类竞赛｜获奖等级：一等奖｜第1 名：100分｜第2 名：90分｜…
```

### 3.5 落点

在 `serialize_groups` 的**行渲染**这一步（与多值展开同一层），对单元格值做归一化。
**不改表格结构、不改列名、不改分组。**

### 3.6 边界与风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 未来出现「整数但不是分值」的列（如序号、人数） | 会被误加「分」 | 加一道表级守卫：**若该表存在表头含 `序号/编号/人数/人数` 且整列为纯整数，则整表不补单位** |
| 单位不是「分」（如「学时」「次」） | 补错 | 本语料未出现；若出现，以「已带单位」跳过为准，纯整数仍会补「分」——**需人工确认** |
| 补单位后文本变长 | 163 格 × 1 字 ≈ +163 字，占比 <3% | 可忽略 |
| **未测重排影响** | 只验证了安全性，没量分数变化 | 上线前补一次 A/B（见 §4） |
