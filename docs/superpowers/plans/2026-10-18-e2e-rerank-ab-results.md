# 端到端 bge vs jina 精排 A/B（20 题）

**日期：** 2026-10-18  
**脚本：** `backend/tools/e2e_rerank_ab.py`  
**方式：** 走真实图（route → rewrite → retrieve → rerank → build_context → generate → cite），
同一索引、同一生成模型（DeepSeek Flash，temperature=0）、两边 `min_score=0`，
**只切换 reranker 后端**。

## 题目

- **10 道非表格题**：`f-01-04`、`f-02-01`、`f-03-01`、`f-04-01`、`f-05-01`、

- **10 道表格题**：`tq-01` … `tq-10`（二课表格口语题）。
- 旧 doc11/doc12 的期望文档 id 已映射到当前重传后的新 id。

## 关键结果

1. **召回层打平**：候选、精排、证据的期望文档命中都是 **20/20**；表格题目标块命中都是 **10/10**。  
   在这 20 题上，reranker 没有改变“有没有捞到”，差异主要出现在**排序、答案和引用**。
2. **答案正确率**：Jina **20/20**，bge **19/20**。唯一的 bge 错误是 `tq-04`（计算机等级证书）：
   - bge 答成了 doc11 的“全国计算机等级考试二级 20 分”；
   - Jina 答的是 doc12 的“通过各级计算机等级考试并获得证书，3分/项”，并额外说明 doc11 是另一份文件。
   - 这是 doc11/doc12 的**跨文档混淆**，不是目标块没召回：两边证据里都有 doc12 的目标块。
3. **引用命中**：Jina **20/20**，bge **18/20**。bge 在 `tq-04` 和 `f-06-01` 上引到了别的文档；
   `f-06-01` 的答案本身正确，但引用文档不是期望文档。
4. **Top1 文档命中**：两边都是 **17/20**，没有差异。
5. **延迟**：总体接近（bge 4514ms / Jina 4665ms）；表格题 Jina 稍慢（5027ms vs 4748ms）。
6. **置信度**：bge 0.7507、Jina 0.4350，是模型刻度差异，不能据此说 bge 更好。

## 结论

- 这轮端到端 A/B 里，**Jina 略优**：正确率 20/20 vs 19/20，引用命中 20/20 vs 18/20。
- 但差距不大，而且**召回层完全打平**；Jina 的收益主要体现在“把正确文档排在更靠前的位置，生成和引用更少被另一份文件带偏”。
- 如果只看这 20 题，建议继续用 Jina 作为默认；bge 不是不能用，但需要接受跨文档混淆和引用偏差的风险。
- 这轮也说明：**rerank 分数/排名不是唯一指标**；端到端答案和引用更能反映用户实际体验。

## 限制

- 每题只跑一次；LLM 温度设为 0，但远程模型仍有轻微非确定性。
- LLM 判正确用的是 DeepSeek Flash 作为 judge，存在判官噪声。
- 非表格题两边都 10/10，存在地板效应；差异主要由表格题和引用体现。
- 20 题样本量小，不能外推成“Jina 全面优于 bge”；它只说明这批题上的趋势。
