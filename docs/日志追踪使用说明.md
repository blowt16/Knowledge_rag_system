# 日志追踪使用说明

本文说明后端控制台日志怎么看、怎么调、怎么用 `trace_id` 串起一次请求。

实现设计见 `docs/superpowers/specs/2026-10-19-log-tracing-design.md`。

---

## 1. 控制台一行日志怎么读

```text
18:31:05.772 INFO  [a1b2c3d4] retrieve    ✔ 完成 2717ms  candidates=17 degraded=-
```

| 列 | 含义 |
|---|---|
| `18:31:05.772` | 本地时间，精确到毫秒 |
| `INFO` | 日志级别（DEBUG / INFO / WARNING / ERROR） |
| `[a1b2c3d4]` | `trace_id` 前 8 位；同一次请求的所有行都一样 |
| 缩进 | 阶段层级：HTTP/chat 在最左，图节点缩进 2 格，子阶段再缩进 2 格 |
| `retrieve` | 阶段名（ASCII，方便 grep） |
| `✔ 完成` / `✖ 失败` | 阶段状态 |
| `2717ms` | 阶段耗时；超过 1 秒显示为 `2.72s` |
| `candidates=17 degraded=-` | 关键字段；只放数量、耗时、枚举，不放正文 |

失败行示例：

```text
18:31:05.772 ERROR [a1b2c3d4] retrieve    ✖ 失败 2717ms  candidates=0 error=TimeoutError
```

错误堆栈只写进 `logs/app.jsonl`，控制台只显示错误类型，避免刷屏。

## 3. 用 trace_id 排查

- 响应头 `x-trace-id` / `traceparent` 里的值，与控制台 `[...]` 里的前 8 位同源。
- 控制台的 `chat.start` 行会打印完整 `trace_id`；复制它可以直接：
  - 在 `logs/app.jsonl` 里搜 `"trace_id": "<完整值>"`；
  - 在 Langfuse 里搜同一条 trace。
- Langfuse 关闭时也会生成本地 `trace_id`，不再是一串 0。

## 4. 配置

`backend/app/config/app.yaml`：

```yaml
logging:
  default_level: INFO
  console_level: INFO        # 控制台独立级别
  console_format: text       # text | json
  console_color: auto        # auto | always | never
  console_max_value_chars: 120
```

常用组合：

| 场景 | 设置 |
|---|---|
| 日常开发，看主流程 | 默认 `INFO` |
| 排查检索/精排细节 | `LOG_LEVEL=DEBUG` |
| 控制台太吵，只看文件 | `console_level: WARNING` |
| 终端颜色乱码 | `console_color: never` |
| Docker / 采集 JSON | `console_format: json` |

> `console_level` 不能低于 root 级别；要看 DEBUG 子阶段必须设 `LOG_LEVEL=DEBUG`。

---

## 5. 隐私约束

- 不记录 query / answer / prompt / 检索正文。
- query 只记 `query_len` 和 `query_hash`。
- 所有字段值截断到 `console_max_value_chars`，并去掉换行，防止日志注入。
- 需要看正文时，用 `trace_id` 去 `qa_logs` 或 Langfuse 查；那里有 ACL 和脱敏约束。

---

## 6. 常见问题

**控制台只有 JSON？**
`console_format` 被设成了 `json`，改回 `text`。

**看不到子阶段？**
默认 INFO 只显示主流程；设 `LOG_LEVEL=DEBUG`。

**一次请求的 trace_id 是 `--------`？**
说明日志不在任何 trace 上下文里（例如启动日志、CLI 外部调用）。请求内不会出现。

**uvicorn 的访问日志去哪了？**
已关闭默认 access logger，由 `http` 阶段行统一输出，避免每个请求两行。
